# OpenAI Codex CLI & App Adapter

`veycraft` works natively with **OpenAI Codex CLI** (`codex`) and **Codex Desktop** using `AGENTS.md`, `agentskills.io` `.agents/skills/*/SKILL.md` discovery, and TOML `[mcp_servers.*]` configuration.

## 1. Zero-Config Global Setup (Recommended)
Run once from anywhere:
```bash
npx github:redasalem/veycraft init --global --ide codex
```
What this configures automatically (without overwriting your existing personal rules or unrelated TOML tables):
1. Installs universal user skills into `~/.agents/skills/` (`daily-run`, `quick-tailor`, `demo`, `tailor-cv`, `apply-url`, `linkedin-growth`, `offer-negotiator`, and more).
2. Safely appends/updates a managed `<!-- veycraft:start -->` block in `$CODEX_HOME/AGENTS.md` (default: `~/.codex/AGENTS.md`) pointing Codex to `~/.veycraft/AGENTS.md` and `skills/REGISTRY.md`.
3. Safely adds `[mcp_servers.playwright]` (with `--user-data-dir=` pointing to `~/.veycraft/browser-profile` and Windows `cmd /c npx` wrapping when needed) to `$CODEX_HOME/config.toml` (default: `~/.codex/config.toml`), plus `[mcp_servers.notion]` if `NOTION_TOKEN` is set.

## 2. Local Repository Usage
Inside any cloned `veycraft` checkout or local `init --ide codex` workspace:
- Codex automatically reads `AGENTS.md` (capped at `project_doc_max_bytes`, default 32 KiB) and `.agents/skills/*/SKILL.md`.
- `.codex/config.toml` (generated by `init` / `sync-mcp`, gitignored) wires `[mcp_servers.playwright]` locally without leaking paths.
- Start with offline tasks (`"Review my CV"`, `"/quick-tailor"`, `"Improve my LinkedIn headline"`) — no Playwright MCP or login needed.

## 3. Model & Safety Notes (`GPT-5` / `o-series`)
- Follow [`adapters/models/openai.md`](../models/openai.md): never run parallel browser clicks; wait `3–9s` between Playwright steps and re-read fresh `browser_snapshot` outputs.
- Keep `approval-mode` safe (`on-request` / `untrusted`): never auto-submit forms without an explicit job-bound human `APPROVE`.
